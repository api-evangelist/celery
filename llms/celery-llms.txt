# Celery

> Celery is a BSD-licensed open-source distributed task queue for Python. It runs work
> asynchronously in the background across a pool of workers, using a message broker (RabbitMQ,
> Redis, Amazon SQS and other Kombu transports) to carry task messages and a result backend
> (Redis, RPC, database, Memcached, Cassandra, S3) to carry results. Celery is a LIBRARY, not a
> hosted service: there is no HTTP API, no base URL, no account and no API key. Its public
> interfaces are Python programming APIs plus a documented broker message protocol.

## What an agent needs to know first

- There is nothing to call over the network. To use Celery an agent must be running inside a
  Python process that has the `celery` package installed and an app configured against a broker.
- Delivery is AT-LEAST-ONCE. A task can execute more than once if a worker dies mid-execution.
  Celery provides no idempotency key and no replay protection; the documentation instructs
  developers to write idempotent task bodies. Assume duplicates.
- `apply_async` / `delay` can be undone with `revoke()` BEFORE the task starts executing, or with
  `revoke(terminate=True)` while it is running (prefork and eventlet pools only). `purge` cannot be
  undone at all — the docs warn messages are permanently deleted.
- Remote control and inspect commands only work on the amqp and redis brokers.

## Core interfaces

- [Task API](https://docs.celeryq.dev/en/stable/userguide/tasks.html): defining and executing
  tasks — decorators, retries, `autoretry_for`, `retry_backoff`, time limits, rate limits, custom
  task classes. Reference: https://docs.celeryq.dev/en/stable/reference/celery.app.task.html
- [Application API](https://docs.celeryq.dev/en/stable/userguide/application.html): configuring
  brokers, result backends, serialization, routing and task discovery. Reference:
  https://docs.celeryq.dev/en/stable/reference/celery.html — settings:
  https://docs.celeryq.dev/en/stable/userguide/configuration.html
- [Canvas API](https://docs.celeryq.dev/en/stable/userguide/canvas.html): workflow composition —
  signatures, chains, groups, chords, maps, starmaps, chunks.
- [Beat API](https://docs.celeryq.dev/en/stable/userguide/periodic-tasks.html): periodic tasks with
  crontab, interval and solar schedules. Reference:
  https://docs.celeryq.dev/en/stable/reference/celery.beat.html
- [Worker API](https://docs.celeryq.dev/en/stable/userguide/workers.html): execution pools
  (prefork, gevent, eventlet, solo, threads), autoscaling, remote control, revocation.
  Reference: https://docs.celeryq.dev/en/stable/reference/celery.worker.html
- [Result Backend API](https://docs.celeryq.dev/en/stable/userguide/tasks.html#result-backends):
  storing and retrieving task state and results. Reference:
  https://docs.celeryq.dev/en/stable/reference/celery.result.html
- [Signals API](https://docs.celeryq.dev/en/stable/userguide/signals.html): task, worker, beat and
  consumer lifecycle hooks. Reference:
  https://docs.celeryq.dev/en/stable/reference/celery.signals.html
- [Monitoring and Events API](https://docs.celeryq.dev/en/stable/userguide/monitoring.html):
  inspect/control commands and the worker event stream. Reference:
  https://docs.celeryq.dev/en/stable/reference/celery.events.html

## What Celery does not publish

- No OpenAPI, Swagger, GraphQL, gRPC/Protobuf or WSDL contract — there is no network API to describe.
- No AsyncAPI. The event stream in this repository (asyncapi/celery-events-asyncapi.yml) was derived
  by API Evangelist from the published Event Reference; it is not a provider artifact.
- No /.well-known/ discovery documents, no A2A agent card, no MCP server (first-party or hosted).
- No pricing, plans, sign-up, terms of service or privacy policy — it is a library, not a service.
- No status page or SLA — nothing is hosted.
- No security.txt; vulnerability reports go through the GitHub security policy.
- The project website celeryq.dev no longer resolves and www.celeryq.dev now serves a domain parking
  page. Only docs.celeryq.dev (Read the Docs) is live.
